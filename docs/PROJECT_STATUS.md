# RM2027 工程机器人上位机阶段进度与后续验证

更新日期：2026-10-18  
技术环境：Ubuntu 22.04 / ROS 2 Humble / BIT 视觉 / MoveIt 2 / Panthera FakeSystem

## 1. 目标与边界

**当前阶段目标**：利用录制视频中的兑换装置检测结果，计算装配柱候选接近位姿，驱动 Panthera 机械臂在 RViz/FakeSystem 环境下完成受控的 MoveIt 2 规划和预接近动作。

**后续工程目标**：部署真实摄像头、机械臂、DM-MC02 与关节反馈，完成标定、抓手控制、完整兑换动作及误差与安全性测试。

上述两个阶段独立验收；软件仿真成功不能替代实机验收。

## 2. 系统组成

- **BIT_RM_eng_vision**：图像获取、YOLO-Pose 检测、PnP 位姿求解与相关标定模块。
- **engineer_moveit_ws**：目标坐标转换、装配柱几何推算、视觉目标与运动规划桥接。
- **Panthera-HT_ROS2**：机械臂结构模型、MoveIt 2 配置与 FakeSystem/RViz 仿真（计划复制至 `rm2027/`）。
- **dm_mc02_comm**：独立 USB CDC 通信实验工程，尚未接入完整控制链路。

参见仓库首页 [README](../README.md) 的目录树、程序流程图和完整仿真启动指令。

## 3. 已验证结果

1. BIT 视频、关键点检测、PnP 输出可正常运行；`/pnp/pose_1` 提供检测位姿。
2. 在模拟相机 TF 正常发布的条件下，`tf_bridge` 将 PnP 结果转换为 `base_link` 坐标系下的米制位姿。
3. `pillar_target_generator.py` 根据参考位姿生成装配柱特征面中心和 ± 方向候选点，并通过 Marker 在 RViz 可视化。
4. Panthera MoveIt 2 在人工给定可达目标下已经成功规划，FakeSystem 已完成运动执行。
5. `planner_bridge` 可以接收 `/vision/target_pose_base`；尚未完成真实视觉候选点的 Plan + Execute 联合验收。
6. 新一组仿真相机外参下，两个视觉候选接近点在**单位四元数**姿态、开启和关闭碰撞检查的测试中均返回 IK 成功；保留原始视觉四元数时均返回 `NO_IK_SOLUTION`。

> 测试数据由持续变化的视频帧产生，示例坐标仅代表当时样本，不能当作静态标定坐标或最终抓取精度。

## 4. 当前主要问题

### P0：从视觉候选位置到正确 TCP 位姿，并完成 Plan + Execute

现阶段视觉位置与目标几何推算已基本打通，但 BIT 提供的目标四元数**不等同于夹爪所需的末端朝向**。目前可达性测试中的单位四元数仅用于诊断和验证链路，不是正式装配姿态。

需要确定：

- 装配柱局部坐标轴与具体接近方向；
- 工具末端 `bat_center` 的真实 TCP 位置与开口方向；
- 装配柱目标到 TCP 的相对刚体变换；
- 两候选接近点的筛选规则及偏移量；
- 完整 MoveIt 2 规划能否避开机械臂自身与场景障碍；
- FakeSystem 执行后的末端位姿与预期目标误差。

验收标准：BIT 实时视频帧 → 视觉目标位姿 → 正确 TCP 预接近位姿 → MoveIt 2 规划成功 → FakeSystem 仿真执行成功，均有日志与 RViz 记录。

### P1：模拟相机 TF 未稳定随 Launch 发布

修改 `bit_moveit_pipeline.launch.py` 中模拟相机外参后，曾出现 `/pnp/pose_1` 有数据、`/vision/reference_pose_base` 无数据的情况。手动运行 `static_transform_publisher` 后，TF 和下游装配柱数据恢复。

已测试的**仿真场景对齐**参数：

```text
base_link -> bit_camera_optical
translation (m): [-0.25, -0.05, 0.80]
roll=-1.57079632679, pitch=0, yaw=-1.57079632679
```

需要检查 Launch 实际进程日志、节点是否存在、静态 TF 是否成功发布、节点名和帧名是否一致。**根因尚未确定**，不可将手动绕过视为永久修复。实机时这些参数必须由实际标定替换。

## 5. 其他需要确认的技术事项

| 事项 | 当前情况 | 验收要求 |
| --- | --- | --- |
| 机械臂实际模型 | Xacro 与 URDF 中部分关节定义存在差异 | 确认启动时加载的版本，并对照硬件核验 |
| TCP `bat_center` | 模型内对 `link6` 有固定 +X 0.18m 偏移，尚未经实机核实 | 完成 TCP 与工具开口轴标定 |
| 场景碰撞 | 候选 IK 测试通过不代表轨迹一定存在 | 加入兑换装置基本碰撞体，验证 Plan |
| 视觉稳定性 | 视频中的 PnP 输出存在帧间变化 | 建立筛选、滤波、超时和触发阈值 |
| 启动复现 | 部分节点此前通过独立终端手动启动 | 统一 Launch，验证重启后仍可复现 |
| 抓手动作 | 夹爪控制器状态尚未完成统一验收 | 定义并验证开闭接口与动作序列 |
| USB CDC / DM-MC02 | 曾接收到控制板反馈帧，但六关节指令完整解析及执行未确认 | 协议、计数反馈、关节状态、急停与超时验收 |
| 第三方资源 | BIT、Panthera 及模型素材包含上游资源 | 保留许可证并核查公开分发权限 |
| 仓库卫生 | `engineer_vision_tf_bridge` 中有名称异常的杂项文件 | 检查用途后清理，禁止直接删除未核实内容 |
