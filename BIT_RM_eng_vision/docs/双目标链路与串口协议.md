# 双目标视觉链路与串口协议

本文档描述 detect → PnP → TF → comm 的双目标数据约定，以及 PC 与下位机之间的串口协议。

## 1. 基本约定

- 长度单位：毫米（mm）
- 角度单位：度（deg）
- 串口字节序：小端（Little-Endian）
- 目标槽位：
  - right：ROS topic 后缀 `_1`
  - left：ROS topic 后缀 `_2`
- 串口中始终按 right → left 排列。

## 2. 目标配对与左右判定

### 2.1 pillar 与 exchange 配对

使用图像坐标系中的 pose 点进行横向包含判断：

```text
pillar.TL.x > exchange.light_TL.x
pillar.TR.x < exchange.light_TR.x
```

配对判定完全沿用原 `double_detect.py`：四个关键点字典必须存在，
随后直接比较其 x 坐标；配对阶段不额外检查关键点 score。

### 2.2 槽位分配

- 没有目标：right、left 均为空。
- 只有一个目标组：
  - 单 pillar
  - 单 exchange
  - 已配对的 pillar + exchange
  - 以上情况均固定放入 right，left 为空。
- 有两个目标组：按目标组图像中心 x 排序：
  - x 较小：left
  - x 较大：right
- 不进行跨帧身份跟踪。双目标退化成单目标时，剩余目标重新归入 right。
- 原 `double_detect` 的失败行为保持不变：
  - `2p+2e` 两种配对方式均失败：两侧清空。
  - `2p+1e` 或 `1p+2e` 无法找到配对：两侧清空。
  - `1p+1e` 无法配对：拆成两个单类目标，再按 x 分左右。

### 2.3 单类目标

任一侧允许只看到 pillar 或只看到 exchange：

- pillar：使用4个角点，至少4个有效点才能独立 PnP。
- exchange：共有7个点，至少4个有效点才能独立 PnP。
- 缺失类别对应的 mask bits 保持为0。

## 3. ROS 链路

```text
/detect/poses_and_bboxes
        |
        v
     pnp_node
        |-- /pnp/pose_1 --------> tf_node --> /world/object_rpy_1 --> comm
        |      right                              right
        |
        |-- /pnp/pose_2 --------> tf_node --> /world/object_rpy_2 --> comm
        |      left                               left
        |
        `-- /pnp/point_mask -------------------------------> comm
```

### 3.1 `/detect/poses_and_bboxes`

- 类型：`std_msgs/String`
- 内容：紧凑 JSON

```json
{
  "header": {
    "stamp": {"sec": 0, "nanosec": 0},
    "frame_id": "camera"
  },
  "frame_sequence": 1,
  "detections": {
    "pillar": [
      {
        "class_name": "pillar",
        "score": 0.99,
        "bbox": [0, 0, 100, 100],
        "pose": {
          "TL": {"x": 0.0, "y": 0.0, "score": 1.0}
        }
      }
    ],
    "exchange": []
  }
}
```

### 3.2 `/pnp/pose_1` 与 `/pnp/pose_2`

- 类型：`geometry_msgs/PoseStamped`
- `_1`：right
- `_2`：left
- 坐标系：OpenCV camera
- `position`：XYZ，单位 mm
- `orientation`：物体姿态四元数

### 3.3 `/world/object_rpy_1` 与 `/world/object_rpy_2`

- 类型：`geometry_msgs/PoseStamped`
- `_1`：right
- `_2`：left
- `position.x/y/z`：世界系 XYZ，单位 mm
- `orientation.x/y/z`：Roll/Pitch/Yaw，单位 deg
- `orientation.w`：不使用

### 3.4 `/pnp/point_mask`

- 类型：`std_msgs/UInt32`
- 低16位：right state
- 高16位：left state

每侧16位定义：

| bit | 含义 |
| ---: | --- |
| 0–10 | 11个关键点可见性 |
| 11–14 | 保留，恒为0 |
| 15 | 本帧该侧 PnP 位姿有效 |

```text
UInt32:
31                         16 15                          0
+----------------------------+----------------------------+
|         left state         |        right state         |
+----------------------------+----------------------------+
```

某侧 mask bit0–10 全为0，表示该侧未看到目标或没有任何有效关键点。

## 4. 11点可见性编号

right 与 left 各自使用相同的11点编号：

| bit | 类别 | 关键点 |
| ---: | --- | --- |
| 0 | pillar | `TL` |
| 1 | pillar | `TR` |
| 2 | pillar | `BL` |
| 3 | pillar | `BR` |
| 4 | exchange | `shell_L` |
| 5 | exchange | `shell_M` |
| 6 | exchange | `shell_R` |
| 7 | exchange | `light_TL` |
| 8 | exchange | `light_BL` |
| 9 | exchange | `light_TR` |
| 10 | exchange | `light_BR` |

关键点存在且 `score > 0` 时，对应 bit 为1。

## 5. 串口通用帧

默认串口参数：115200、8N1。

```text
[header] [length] [command] [payload...] [checksum] [tail]
```

| 字段 | 长度 | 说明 |
| --- | ---: | --- |
| header | 1B | 固定 `0xA5` |
| length | 1B | 完整帧长度 |
| command | 1B | 命令字 |
| payload | NB | 命令数据 |
| checksum | 1B | payload 所有字节求和后取低8位 |
| tail | 1B | 固定 `0x5A` |

```text
checksum = sum(payload) & 0xFF
```

## 6. 命令一览

| 命令 | 方向 | 功能 | payload | 整帧 |
| --- | --- | --- | ---: | ---: |
| `0x01` | PC → MCU | right/left 双位姿 | 52B | 57B |
| `0x02` | MCU → PC | 开始发送0x01 | 0B | 5B |
| `0x03` | MCU → PC | 停止发送0x01 | 0B | 5B |
| `0x04` | PC → MCU | right/left 双 mask | 4B | 9B |
| `0x05` | MCU → PC | 相机 IMU | 16B | 21B |

## 7. 命令 `0x01`：双目标位姿

payload 格式：

```text
<i12f
```

| payload偏移 | 类型 | 字段 |
| ---: | --- | --- |
| 0 | `int32` | count |
| 4 | `float32` | right X |
| 8 | `float32` | right Y |
| 12 | `float32` | right Z |
| 16 | `float32` | right Yaw |
| 20 | `float32` | right Pitch |
| 24 | `float32` | right Roll |
| 28 | `float32` | left X |
| 32 | `float32` | left Y |
| 36 | `float32` | left Z |
| 40 | `float32` | left Yaw |
| 44 | `float32` | left Pitch |
| 48 | `float32` | left Roll |

整帧长度：

```text
3 + 52 + 2 = 57 bytes
```

某侧满足以下任一条件时，该侧6个浮点数全部发送0：

- 该侧 mask 为0
- 本帧该侧 PnP 无效
- 世界位姿尚未到达 comm

PC 收到 `0x02` 后开始周期发送 `0x01`，收到 `0x03` 后停止。

## 8. 命令 `0x04`：双侧关键点 mask

payload 格式：

```text
<HH
```

| payload偏移 | 类型 | 字段 |
| ---: | --- | --- |
| 0 | `uint16` | right mask |
| 2 | `uint16` | left mask |

仅发送各侧 bit0–10；ROS state 中的 bit15 PnP-valid 不发送给下位机。

整帧长度：

```text
3 + 4 + 2 = 9 bytes
```

示例：

```text
right mask = 0x0401
left mask  = 0x0202

A5 09 04 01 04 02 02 09 5A
```

`0x04` 始终约30Hz发送，不受 `0x02`/`0x03` 控制。

## 9. 命令 `0x02` 与 `0x03`

无 payload：

```text
0x02: A5 05 02 00 5A
0x03: A5 05 03 00 5A
```

- `0x02`：允许PC发送 `0x01`
- `0x03`：停止PC发送 `0x01`
- 不影响 `0x04`

## 10. 命令 `0x05`：相机 IMU

方向：MCU → PC。

payload 格式：

```text
<ifff
```

| payload偏移 | 类型 | 字段 |
| ---: | --- | --- |
| 0 | `int32` | count |
| 4 | `float32` | Yaw |
| 8 | `float32` | Pitch |
| 12 | `float32` | Roll |

整帧长度：

```text
3 + 16 + 2 = 21 bytes
```

comm 发布 `/camera/imu_rpy`：

- `vector.x` = Roll
- `vector.y` = Pitch
- `vector.z` = Yaw

相机姿态参数默认值以 `tf_pkg/tf_pkg/tf_node.py` 为唯一来源。Shell 和 systemd 只在显式设置 `CAMERA_*` 或 `IMU_TIMEOUT_S` 时覆盖。

## 11. 下位机解析注意事项

1. 必须按帧头 `0xA5` 重新同步。
2. 必须检查 length、checksum 和帧尾。
3. 不要再按旧协议固定读取33B的 `0x01` 或7B的 `0x04`。
4. C/C++ 结构体可能包含对齐填充，建议逐字段解析；若直接映射结构体，必须显式 packed。
5. 浮点格式要求 IEEE-754 float32。
6. right 永远在 left 前面。

## 12. 部署

旧装机升级：

```bash
./scripts/autostart/patch_autostart_dual_target.sh
```

清除旧的Shell相机参数覆盖，恢复Python默认值：

```bash
./scripts/autostart/patch_autostart_imu.sh
```

协议不向后兼容。运行补丁并重启服务前，必须先确认下位机已支持57B `0x01` 和9B `0x04`。
